## 2. Component‑Specific Findings

### 2.1 JUCE VST3 Plugin (`plugin-aifred/`)
- **Source language:** C++ (JUCE framework). 
- **Key UI files:** `Source/AifredLookAndFeel.cpp` (custom LookAndFeel), various UI components under `Source/`. 
- **Build system:** CMake (invoked by CI workflow). 
- **Packaging:** Windows installer/ZIP and macOS PKG are produced (see `docs/RELEASE_NOTES.md`). 
- **Tests:** No dedicated test suite observed in the repository (UNVERIFIED).

### 2.2 Local AI Engine (`tools/AifredEngine/`)
- **Entry point:** `Program.cs` (C# console app). 
- **Runtime endpoints:** HTTP gateway at `http://127.0.0.1:8787`; forwards to Ollama (`http://127.0.0.1:11434`) or OpenAI (`https://api.openai.com/v1/responses`). 
- **Health endpoint:** `/health` returns JSON with `ok` and `model_loaded` (referenced by `tools/check_integrity.py`). 
- **Cross‑platform binaries:** Built for Windows and macOS, bundled with plugin installers. 
- **Configuration defaults:** Installer writes default Ollama config; engine logs to user‑data folder when install root is unwritable (INFERRED from release notes). 
- **Tests:** No unit‑test code observed (UNVERIFIED).

### 2.3 Cloudflare Website & Backend (`apps/website/`)
- **Static assets:** HTML/CSS/JS under the root and `assets/` (audio catalog fallback). 
- **Worker entry point:** `_worker.js` (Cloudflare Pages worker). 
- **API routes:** Implemented in `functions/api/v1/[[path]].js` (e.g., catalog loading, admin authentication, download‑session stub). 
- **WebSocket chat:** `functions/ws/chat.js` provides real‑time chat for the admin console and website. 
- **Authentication:** Simple token‑based admin session using SHA‑256 of `username|issuedAt|nonce|secret` (observed in code). 
- **R2 / KV bindings:** `AIFRED_WEBSITE_ASSETS`, `AIFRED_DOWNLOADS`, `AIFRED_REFERENCE_POOL`, `AIFRED_REFERENCE_BUCKET` (referenced in code and `wrangler.toml`). 
- **PayPal integration:** Stubbed route `create-download-session` returns 501 with explanatory message (INFERRED that production integration lives elsewhere). 
- **Tests / CI:** GitHub Actions builds and deploys the site; no explicit test suite in `apps/website/` (UNVERIFIED).

### 2.4 Android Admin Console (`apps/admin-android/`)
- **Platform:** Kotlin + Jetpack Compose, Gradle‑based. 
- **Purpose:** Owner‑only UI for managing backend (chat, uploads, catalog, sales, activity). 
- **Build instructions:** `./gradlew.bat assembleDebug` (README). 
- **Distribution policy:** Private, never published to public releases (OBSERVED in README). 
- **Tests:** No test module observed (UNVERIFIED).

### 2.5 Cloudflare Infrastructure (`infra/cloudflare/`)
- **Configuration files:** `wrangler.toml` (both at repo root and under `apps/website/`). 
- **Bindings:** KV, R2, environment variables for admin credentials and API tokens. 
- **Observations:** No explicit Terraform/Pulumi scripts; configuration is declarative via Wrangler.

### 2.6 CI / Release Automation
- **GitHub Actions:** Build, test (for the plugin and website), upload artifacts, create GitHub releases. 
- **Release scripts:** `tools/release/aifred_admin_dryrun_check.py` validates Android admin path without building. 
- **Packaging verification:** `tools/check_integrity.py` validates Windows zip contains VST3, engine executable, and config, and checks engine health endpoint.
