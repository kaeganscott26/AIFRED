# AIFRED User Configuration

This directory contains **blank distribution-safe configuration templates**. It must never contain a North3rnLight3r operator credential or a user's populated provider key.

## LLM provider setup

AIFRED DSP, observation and deterministic context operate independently of an LLM. Conversational interpretation requires one supported provider:

- local Ollama;
- OpenAI; or
- a supported OpenAI-compatible endpoint.

The default example targets local Ollama:

```json
{
  "provider": "ollama",
  "endpoint": "http://127.0.0.1:11434",
  "model": "aifred:latest",
  "api_key": "",
  "timeout_ms": 180000
}
```

For OpenAI or another compatible provider, replace the provider, endpoint and model and supply the user's own API key locally.

## Local settings ownership

Beta AifredIntelligenceHost persists its runtime provider settings under:

```text
%APPDATA%/Aifred/beta/IntelligenceHost/settings.json
```

The host also supports `AIFRED_PROVIDER`, `AIFRED_PROVIDER_ENDPOINT`, `AIFRED_PROVIDER_MODEL`, and `AIFRED_PROVIDER_API_KEY` environment overrides.

## Context is provider-independent

AIFRED measurements and deterministic context are not generated by the LLM. The intelligence architecture keeps AIFRED-owned session context separate from whichever supported model interprets it.

The intended active-memory contract is the current session plus the previous nine retained sessions. Context/history exports are portable user-owned data and can be supplied by the user to other capable applications such as ChatGPT or Gemini for interpretation. Those applications are external to AIFRED and use their own terms/privacy policies.

## Security

Never distribute a populated API key. AIFRED's local plugin/host does not require Cloudflare, GitHub or R2 credentials.
